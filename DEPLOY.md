# Развёртывание на сервере АФМ

Проект = **5 сервисов**, которые крутятся вместе (лучше на GPU-сервере):

| Сервис | Порт | venv | Что делает |
|--------|------|------|-----------|
| Основной API | 8000 | `.venv` | оркестратор + STT-роутинг + вызов RAG/TTS |
| RAG-сервис | 8077 | `rag/.venv` | ответ строго по базе РК (LightRAG + LLM/эмбеддинги АФМ) |
| **video_ui (фронтенд)** | **8100** | `.venv` | **киоск-страница «видео-аватар»: ролики, таблицы/графики, QR, печать бланков; вопросы проксирует на :8000. Это то, что видит гражданин** |
| F5-сервер | 8810 | `.venv-f5` | русский TTS (F5-TTS + ударения; референс refs/ref_ru_f5.wav) — опц., локальный TTS |
| Spark-сервер | 8809 | `.venv-spark` | казахский TTS — опц., офлайн-фолбэк |

`video_ui` **своего venv не требует** — работает в основном `.venv` (fastapi/uvicorn/httpx
уже там), отдельного шага установки у него нет.

⚠️ **venv `rag/` нельзя сливать с основным** — `lightrag`/`torch` конфликтуют с голосовым слоем.

## (Рекомендуется) Установка через uv — быстрее и воспроизводимее

`uv` — быстрый менеджер пакетов (замена pip). Ставит в разы быстрее (а у нас 4 venv) и
фиксирует версии через lock — это снимает риск «на Mac работает, на сервере нет».
Зависимости каждого сервиса объявлены в его `pyproject.toml`; `requirements.txt` —
закреплённый список для установки/лока.

**Поставить uv один раз** (нужен интернет; офлайн — взять бинарь заранее):
```bash
curl -LsSf https://astral.sh/uv/install.sh | sh      # или: pip install uv
```

- В шагах ниже команды даны на `uv`. Без `uv` — те же команды с обычным `pip` (рабочий фолбэк).
- `setup.sh` у F5/Spark **сами используют `uv`, если он установлен** (иначе pip) — менять ничего не нужно.
- **Зафиксировать точные версии (lock)** на машине с интернетом — по разу на сервис:
  ```bash
  uv pip compile pyproject.toml -o requirements.txt          # корень и rag/ (из их папок)
  ```
  Полученные `requirements.txt` коммитишь и везёшь на сервер — установка станет
  полностью воспроизводимой (включая транзитивные зависимости).

## ШАГ 1. Доставить проект на сервер

**Копировать с Mac НЕ нужно.** В репозитории лежит всё, что требуется деплою:
код, база знаний `rag/data/`, ролики аватара `video_ui/static/video/*.mp4` (21 МБ),
образцы голоса `refs/*.wav`, словарь `rag/vendor/tiktoken/`, юниты `deploy/`.
Единственное, чего в git нет и не будет, — **`.env` с секретами** (ключ ElevenLabs);
он собирается на сервере из `.env.example` на шаге 6.

⚠️ **venv и индекс НЕ переносим** — они пересоздаются на месте (шаги 2–3): сборки под
macOS на Linux не работают.

### Вариант А (основной) — `git clone` на сервере
Годится, если с сервера виден GitHub (проверка — ШАГ 0):
```bash
git clone https://github.com/RaiymbekRszhan/afm-ai-dos.git ~/STT
cd ~/STT
```
Обновление потом — без всякого копирования:
```bash
cd ~/STT && git pull
sudo systemctl restart ai-dos-api ai-dos-video-ui     # и ai-dos-rag, если менялась rag/data (+ ingest)
```

### Вариант Б — сервер без интернета (снимок одним файлом)
GitHub с контура АФМ (`192.168.165.x`) недоступен, поэтому снимок берётся на машине
с репозиторием (Mac, ноутбук с git) и везётся одним файлом ~31 МБ:
```bash
git archive --format=tar.gz -o ai-dos.tar.gz main     # снимок ветки main, без .git
scp ai-dos.tar.gz ПОЛЬЗОВАТЕЛЬ@СЕРВЕР:~/
ssh ПОЛЬЗОВАТЕЛЬ@СЕРВЕР 'mkdir -p ~/STT && tar -xzf ~/ai-dos.tar.gz -C ~/STT'
```
Обновление = новый архив тем же способом (это снимок, `git pull` на сервере не будет).
Нужна история git на сервере — вместо архива `git bundle create ai-dos.bundle main`
и `git clone ai-dos.bundle ~/STT` (файл заметно больше: в истории лежат старые артефакты).

## ШАГ 2. Основной API (venv .venv)
```bash
cd ~/STT
uv venv .venv && source .venv/bin/activate     # без uv: python3 -m venv .venv && source .venv/bin/activate
uv pip install -r requirements.txt             # без uv: pip install -r requirements.txt
deactivate
```
Базовый стек **лёгкий, без torch/CUDA**: казахский STT идёт на сервер АФМ (:8804), казахский
TTS — на ElevenLabs (или Spark :8992). Локальный Whisper-kk (`STT_KK_USE_WHISPER=true`) нужен
РЕДКО — тогда дополнительно `pip install -r requirements-whisper-kk.txt` (на CPU-машине сперва
CPU-сборку torch, см. файл; модель Whisper-kk ~1.6 ГБ скачается при первом казахском запросе).

## ШАГ 3. RAG-сервис (venv rag/.venv)
```bash
cd ~/STT/rag
uv venv .venv && source .venv/bin/activate     # без uv: python3 -m venv .venv && source .venv/bin/activate
uv pip install -r requirements.txt             # без uv: pip install -r requirements.txt (LightRAG==1.4.9.10)
cp .env.example .env                   # проверь LLM_BASE_URL / LLM_MODEL
python -m scripts.check                # покажет реальную размерность эмбеддинга
                                       #   (qwen3-embedding-8b = 4096) → EMBEDDING_DIM в .env
python -m ragsvc.ingest                # построить индекс базы в rag_storage/
cd .. && deactivate
```
> ⚠️ Индексация — **только векторный поиск** (граф знаний не используется): зовёт лишь
> эмбеддинги (минуты), без нагрузки на LLM. Качество подтверждено eval (см. `rag/eval/`).
> `ingest` возобновляемый: при обрыве просто запусти снова.

> ⚠️ **Словарь tiktoken — завендорен, копировать обязательно.** LightRAG при старте
> берёт словарь токенизатора; без кэша tiktoken лезет в интернет (`openaipublic.blob...`)
> и на офлайн-сервере RAG **не стартует** (симптом: `NameResolutionError ... o200k_base.tiktoken`).
> Лекарство: папка `rag/vendor/tiktoken/` должна приехать вместе с проектом, а переменная
> `TIKTOKEN_CACHE_DIR` указывать на неё (в `run_api.sh` и `deploy/ai-dos-rag.service` уже
> прописано). Пересоздать папку (на машине с интернетом):
> `TIKTOKEN_CACHE_DIR=$PWD/vendor/tiktoken python -c "import tiktoken; tiktoken.get_encoding('o200k_base')"`.
> Кэш во временной папке ОС ненадёжен — macOS/Linux чистят её при перезагрузке.

## ШАГ 6. Настроить .env (в корне ~/STT)
```bash
cp .env.example .env
```
Проверь/поставь:
```
# внутренние сервисы АФМ (адреса те же)
LLM_BASE_URL=http://192.168.165.2:8901/v1
STT_URL=http://192.168.165.2:8804/transcribe   # 2026-07-03: АФМ перенёс STT с 8004 на 8804
# (эмбеддинги нужны только RAG-сервису — настраиваются в rag/.env, шаг 3, не здесь)

# казахский STT — на сервер АФМ (:8804 тянет и казахский). Whisper на этой машине
# не нужен (torch не тянем). Опц. вынести на отдельный Whisper-сервер (GPU АФМ):
#   STT_KK_URL=http://192.168.165.2:8813/transcribe   (см. whisper_kk_server/README.md)
STT_KK_USE_WHISPER=false

# источник ответа — RAG-сервис
RAG_URL=http://localhost:8077/ask

# Ключи ElevenLabs (облако; ⚠️ НУЖЕН ИНТЕРНЕТ) — только в .env, в git не идут.
# Нужны, если казахский (или весь TTS) идёт на eleven — см. дефолты ниже.
ELEVENLABS_API_KEY=...
ELEVENLABS_VOICE_ID=...
# Размер куска для eleven. 800 (дефолт) = весь ответ ОДНИМ куском: потоковая
# озвучка вырождается, гражданин ждёт полного синтеза (~29 с на 710 символов).
# 200-250 -> 4-5 кусков, первый звук 13-16 с. Мельче вредно: у каждого вызова
# eleven ~2.5 с накладных (замер на сервере АФМ 29.07).
ELEVENLABS_MAX_CHARS=250
# ⚠️ Прокси АФМ вскрывает TLS: сертификат api.elevenlabs.io подписан ИХ корнем,
# которого нет в certifi -> "CERTIFICATE_VERIFY_FAILED: self-signed certificate
# in certificate chain", казахский молча уходит на офлайн-фолбэк.
# ПРАВИЛЬНО — дать процессу корень прокси (это НЕ .env, а переменная окружения:
# pydantic читает .env в свои поля, а httpx смотрит окружение процесса):
#   SSL_CERT_FILE=/opt/ai-dos/ca-bundle.pem bash run_api.sh
# Если сертификат достать не удаётся — отключить проверку (трафик шифрован,
# но подмену сервера не заметим):
ELEVENLABS_VERIFY_SSL=false

# TTS русский — F5 на GPU-сервере АФМ (офлайн, интернет не нужен).
TTS_PROVIDER=f5
F5_URL=http://192.168.165.2:8991/tts
F5_REF_AUDIO=refs/ref_ru_f5_padded.wav  # референс тембра (шлётся в каждый запрос);
                                     # _padded = с тишиной по краям, иначе резкий старт
F5_REF_TEXT=@refs/ref_ru.txt         # "@путь" = прочитать транскрипт из файла

# TTS казахский — spark (офлайн, GPU АФМ) ИЛИ eleven (облако, звучит чище).
TTS_KK_PROVIDER=spark
SPARK_URL=http://192.168.165.2:8992/tts

# Фолбэк движка: основной не ответил -> ответ досинтезирует запасной, и в /voice
# уходит ФАКТИЧЕСКИЙ provider. Дефолты: kk -> spark, ru пуст (F5 — единственный
# офлайн-движок русского, подменять нечем). Отказавший движок не дёргаем
# TTS_FALLBACK_COOLDOWN секунд, иначе каждый вопрос платит полный таймаут облака.
TTS_KK_FALLBACK=spark
TTS_FALLBACK=
TTS_FALLBACK_COOLDOWN=60
# Локальный TTS вместо GPU (когда сервер АФМ недоступен): старт с USE_LOCAL_F5=1
# (русский) и/или USE_LOCAL_SPARK=1 (казахский) — адреса/контракт переключатся сами.
```

> ⚠️ **`bash run_api.sh` перебивает `.env` по провайдерам — дефолты РАЗНЫЕ.**
> Скрипт делает `export TTS_KK_PROVIDER="${TTS_KK_PROVIDER:-eleven}"`, то есть
> читает переменную ОБОЛОЧКИ, а не файл. Итог:
>
> | Как запущено | русский | казахский |
> |---|---|---|
> | `bash run_api.sh` (боевой пилот-дефолт) | F5 (GPU АФМ) | **eleven** + фолбэк Spark |
> | systemd / `uvicorn` руками | из `.env` (`TTS_PROVIDER`) | из `.env` (`TTS_KK_PROVIDER`, дефолт **spark**) |
>
> Поэтому `TTS_KK_PROVIDER=spark` в `.env` НЕ подействует при запуске скриптом —
> нужен `TTS_KK_PROVIDER=spark bash run_api.sh`. Под systemd (боевой 24/7-путь)
> такого расхождения нет: там `.env` — единственный источник (N2).

И в `spark_server/run.sh` поставь `SPARK_DEVICE="cuda"` (для GPU).
LLM/эмбеддинги RAG-сервиса настраиваются отдельно в `rag/.env` (шаг 3).

> **Как оркестратор выбирает контракт F5:** если задан `F5_REF_AUDIO` — шлёт
> multipart `{ref_audio, ref_text, gen_text}` на GPU-сервер (референс в каждом
> запросе); если пусто — прежний JSON `{text, language}` на локальный `f5_server`.
> `run_api.sh` уже настроен на GPU-сервер по умолчанию (`USE_LOCAL_F5=0`) — отдельные
> ключи запуска не нужны. Вернуть локальный русский TTS: `USE_LOCAL_F5=1 bash run_api.sh`
> (адрес и контракт переключатся сами). Казахский Spark на GPU АФМ (`:8992`)
> использует ТОТ ЖЕ JSON-контракт `{text, language}`, что и локальный, — вернуть
> локальный: `USE_LOCAL_SPARK=1 bash run_api.sh` (`SPARK_URL` переключится сам).

**Через systemd:** топология берётся из того же `/opt/ai-dos/.env` — в юните её
дублировать НЕ НАДО. ⚠️ Строки `Environment=F5_URL=…` и т.п. в юните **молча
перебивают `.env`** (переменные окружения приоритетнее файла) — ровно этот баг
чинила находка N2, поэтому их оттуда убрали. Остаётся только отключить локальные
TTS-юниты, если TTS живёт на сервере АФМ:
`systemctl disable --now ai-dos-f5 ai-dos-spark`.

## ШАГ 7. Запустить всё
**Одной командой** (поднимает rag + основной API + video_ui; русский И казахский TTS —
с GPU-сервера АФМ, локальные f5/spark не стартуют; Ctrl-C гасит всё):
```bash
HF_HUB_OFFLINE=1 bash run_api.sh
```
Или вручную по сервисам (tmux). `f5_server`/`spark_server` — только если нужен локальный
TTS (`USE_LOCAL_F5=1` / `USE_LOCAL_SPARK=1`); по умолчанию TTS берётся с GPU АФМ:
```bash
(cd rag && source .venv/bin/activate && uvicorn ragsvc.server:app --host 127.0.0.1 --port 8077)
source .venv/bin/activate && HF_HUB_OFFLINE=1 uvicorn app.main:app --host 0.0.0.0 --port 8000
bash video_ui/run.sh                 # 8100 — киоск-страница (фронтенд), тот же .venv
# локальный TTS (опционально): bash f5_server/run.sh  # 8810 (ru) ; bash spark_server/run.sh  # 8809 (kk)
```
Фронтенд на другой машине (бэкенд по сети) или на другом порту:
```bash
AIDOS_BACKEND=http://192.168.165.10:8000 bash video_ui/run.sh
VIDEO_UI_PORT=8101 bash video_ui/run.sh
```
Открыть киоск: `http://СЕРВЕР:8100/` (микрофон в браузере требует HTTPS или
`localhost` — на Windows-киоске это решает `deploy/kiosk-start.bat`, см. `video_ui/README.md`).

## ШАГ 8. Проверить — приёмка ОДНОЙ командой
```bash
bash scripts/healthcheck.sh          # все сервисы (вкл. фронтенд :8100) + RAG-ответ + TTS (ru/kk), PASS/FAIL
bash scripts/healthcheck.sh --full   # + сквозной голос STT→RAG→TTS (по образцам refs/)
```
Печатает по строке на каждый шаг (✔/✘), в конце — итог и папку с синтезированными
WAV для прослушки. Код выхода 0 = всё прошло (можно использовать как критерий
«деплой принят»). Проверить сервер по сети: `HOST=АДРЕС bash scripts/healthcheck.sh`.

> Если TTS возьмёт на себя АФМ (внешний endpoint) — скрипт это видит по `/health`
> и не пытается пинговать локальные F5/Spark, а помечает TTS как внешний.

## Два TTS-пайплайна: локальный и ElevenLabs

Оба ставятся **один раз** (шаги выше), в `.env` держатся ключи eleven И адреса
F5/Spark сразу (ШАГ 6). Наличие ключа ElevenLabs в `.env` само по себе облако НЕ
включает — **основной** провайдер каждого языка фиксируется при старте процесса
(командой запуска / `.env` под systemd).

**Пилотный дефолт смешанный:** голый `bash run_api.sh` = русский F5 (GPU АФМ) +
казахский **eleven** — казахский на eleven_v3 звучит заметно чище Spark, ради
этого и берут облако.

⚠️ **Фолбэк движка есть** (появился 28.07, раньше в этом месте было написано
обратное): если основной движок не ответил, ответ досинтезирует запасной, и в
`/voice` уходит ФАКТИЧЕСКИЙ `provider` (по нему киоск ставит темп речи).
По умолчанию kk: eleven → **Spark**, ru: без фолбэка. Отказавший движок не
дёргаем `TTS_FALLBACK_COOLDOWN` (60 с) — иначе каждый вопрос платит таймаут
облака (на стенде 27.07: 78 с ожидания и 502 при живом Spark рядом). Это НЕ
делает интернет необязательным: без него казахский звучит голосом Spark.

Все режимы слушают `:8000` и `:8100`, поэтому работает **один за раз**: Ctrl-C
гасит стек, запускаешь другой командой.

```bash
bash run_api.sh                        # ПИЛОТНЫЙ ДЕФОЛТ: ru = F5 (GPU АФМ), kk = eleven (фолбэк Spark)
TTS_KK_PROVIDER=spark bash run_api.sh  # ПОЛНОСТЬЮ ОФЛАЙН: ru = F5, kk = Spark (GPU АФМ), интернет не нужен
USE_ELEVEN=1 bash run_api.sh           # ВСЁ В ОБЛАКО: ru+kk одним голосом на eleven_v3 (фолбэки F5/Spark)
```
(`HF_HUB_OFFLINE=1` в командах больше не нужен — `run_api.sh` выставляет его сам.)
Полностью автономный русский на этой же машине (без GPU АФМ):
`USE_LOCAL_F5=1 F5_URL=http://localhost:8810/tts bash run_api.sh`.

### Сеть — главное отличие на контуре АФМ

| Режим | Куда ходит |
|-------|-----------|
| **Полностью офлайн** (`TTS_KK_PROVIDER=spark`) | только LAN АФМ (LLM `:8901`, STT `:8804`, F5 `:8991`, Spark `:8992`, RAG локально). **Интернет не нужен.** |
| **Пилотный дефолт** (kk = eleven) и **всё в облако** (`USE_ELEVEN=1`) | то же самое **+ наружу** `https://api.elevenlabs.io:443`. |

Контур АФМ (`192.168.165.x`) интернета не даёт, поэтому режимам с eleven киоск-машине
нужен **split routing**: default-маршрут — через интерфейс с интернетом, а на подсеть АФМ
— явный статический маршрут (иначе LLM/STT уходят в default и не достучатся):
```bash
sudo ip route add 192.168.165.0/24 via <шлюз_кабеля_АФМ> dev <интерфейс_АФМ>
```
Проверка перед стартом режима с eleven (оба должны отвечать):
```bash
curl -m5 -I https://api.elevenlabs.io            # наружу жив
curl -m5 http://192.168.165.2:8901/v1/models     # контур АФМ жив
```
Если в АФМ есть прокси — процессу API выставить `HTTPS_PROXY=...` и согласовать с сетевиками
исходящий 443 на `api.elevenlabs.io`. Полностью офлайн-режиму ничего этого не требуется.
⚠️ Прокси АФМ подменяет TLS-сертификаты (`self-signed certificate in certificate chain`) —
это же ломает всё, что лезет наружу мимо вендоренных копий (симптом с tiktoken — шаг 3).

### Характеристики

| | Локальная (F5 + Spark) | ElevenLabs (`eleven_v3`) |
|---|---|---|
| **Интернет** | не нужен | нужен (443 наружу) |
| **Русский** | F5-TTS + RUAccent — хорошо (глотает концы слов → паддинг) | чисто, естественно |
| **Казахский** | Spark — приемлемо | чисто (главная причина брать v3) |
| **Голос** | разные движки/тембры на язык | один голос на оба языка |
| **Задержка** | F5 GPU ~1.5 c/кусок; Spark локально + прогрев модели | сеть round-trip (нестабильно за прокси) |
| **Стоимость** | ~0 (своё железо) | ~$0.08 за озвученный вопрос |
| **Железо** | нужен GPU + память (Spark грузится долго, ест RAM) | почти ничего локально |
| **Приватность** | всё в контуре АФМ | текст ответа уходит в облако (США) — для госоргана взвесить |
| **Риск** | автономно, но качество ниже | зависит от интернета/аптайма API и биллинга |
| **Команда** | `TTS_KK_PROVIDER=spark bash run_api.sh` | `USE_ELEVEN=1 bash run_api.sh` |

Ориентир: пилотный дефолт (ru = F5, kk = eleven) берёт лучшее от обоих — русский
локально и бесплатно, казахский чисто; полностью офлайн — дежурный режим, когда
интернета нет или его не согласовали. Единственное сетевое требование к режимам с
eleven — split routing на киоск-машине.

**Через systemd:** режим задаётся в `/opt/ai-dos/.env` (`TTS_PROVIDER`/
`TTS_KK_PROVIDER`) — переключение = правка `.env` + `systemctl restart ai-dos-api`,
плодить копии юнита не нужно (`USE_ELEVEN` — флаг `run_api.sh`, не переменная
конфига). Приёмка любого режима — `bash scripts/healthcheck.sh` (сам видит по
`/health`, внешний TTS или локальный).

### Локаль и ssh на сервере

Симптом «русские комментарии в `nano` — каша, `perl` сыплет `Setting locale failed`»
лечится с ДВУХ сторон, одной серверной мало:

```bash
update-locale LANG=C.UTF-8            # встроена в glibc, генерировать нечего
sed -i 's/^AcceptEnv/#AcceptEnv/' /etc/ssh/sshd_config   # не брать локаль от клиента
```
macOS присылает `LC_CTYPE=UTF-8` — имени такой локали не существует ни в одной
системе, и клиентское значение приоритетнее серверного `LANG`. Отключение
`AcceptEnv` чинит сразу все клиенты, поэтому править `~/.ssh/config` на каждом
Mac не нужно. `C.UTF-8`, а не `ru_RU.UTF-8`: даёт нужный charmap, но оставляет
сообщения утилит английскими — их удобнее грепать.

⚠️ **Уже открытая ssh-сессия сохраняет старое окружение** — проверять только в
новой (`ssh СЕРВЕР 'locale charmap'` → ждём `UTF-8`).

⚠️ **sshd на Debian 13 работает через сокет-активацию** (`ssh.socket` enabled,
`ssh.service` поднимается по требованию). Отсюда два капкана:
- `systemctl reload ssh` **убивает демона**: по SIGHUP он перезапускается и
  пытается сам занять порт, который держит systemd → `fatal: Cannot bind any
  address`. Перезапуск — `systemctl restart ssh.socket`;
- `sshd -t` вне юнита выдаёт `Missing privilege separation directory: /run/sshd`
  — это НЕ ошибка конфига, каталог создаёт юнит. Проверять после `mkdir -p /run/sshd`.

Если на автозапуск включены оба (`ssh.socket` и `ssh.service`), они дерутся за порт
на каждой загрузке: оставить сокет, `systemctl disable ssh.service`. После этого
`is-active=active` при `is-enabled=disabled` — норма, демона поднимает сокет.

## Обновление уже развёрнутого сервера

**Основной способ — через git** (на сервере АФМ он установлен 2026-07-29,
Debian 13 trixie; интернет там есть, `deb.debian.org` и GitHub доступны):

```bash
bash scripts/update_server.sh --dry-run    # что приедет и что перезапустится
bash scripts/update_server.sh              # fetch + reset --hard + точечный перезапуск
```
Сервер тянет код **с GitHub сам**, поэтому скрипт сначала предупреждает о
незапушенных коммитах и незакоммиченном дереве — иначе легко выкатить «почти то,
что вижу». Перезапускает только те сервисы, чей код действительно менялся
(`app/` → api, `rag/ragsvc/` → rag, `video_ui/*.py` → video-ui); правки в
`video_ui/static/**` подхватываются без перезапуска — статику uvicorn читает с
диска на каждый запрос. Не трогает `.env`, `.env.*`, `rag/rag_storage/`, venv,
`logs/`, `vendor/`: `reset --hard` не удаляет неотслеживаемое, а `git clean` не
зовётся сознательно.

Ручной эквивалент, если скрипт недоступен:
```bash
ssh root@10.10.42.44 'cd /root/afm-ai-dos && git fetch origin && git reset --hard origin/main'
ssh root@10.10.42.44 'systemctl restart ai-dos-api'
```
`reset --hard`, а не `pull`: он идемпотентен и не встаёт колом, если файл на
сервере кто-то поправил руками — а это ровно то, что там уже случалось с юнитами.

⚠️ **Живые юниты в `/etc/systemd/system/` — отдельные копии**, подогнанные под
сервер (`/opt/ai-dos` → `/root/afm-ai-dos`, `User=ai-dos` → `User=root`).
Обновление кода их НЕ трогает; если менялись `deploy/ai-dos-*.service`, перенести
руками и `systemctl daemon-reload`.

**Запасной способ — снимок** (`scripts/deploy_snapshot.sh`), если GitHub из сети
АФМ закроют. У него два известных изъяна: tar не удаляет исчезнувшие файлы и не
обновляет `.git`, поэтому после снимка индекс надо чинить тем же
`git fetch && git reset --hard origin/main`.

### Как сверить чужой сервер перед первым обновлением

```bash
ssh root@СЕРВЕР 'cd /root/afm-ai-dos && git fetch origin && git status --porcelain'
ssh root@СЕРВЕР 'cd /root/afm-ai-dos && git diff --ignore-cr-at-eol --stat origin/main'
```
⚠️ **`git diff` не видит неотслеживаемые файлы.** Если индекс на сервере отстал
(снимок его не обновляет), файлы, добавленные в новых коммитах, физически лежат
на диске, но для git их нет — и diff показывает их как «удалённые целиком».
29.07 это дало ложную тревогу «на сервере нет `vad.js`, киоск не записывает»,
хотя файл был на месте. Проверяйте такие находки напрямую (`ls`, `curl`), а
число удалённых строк сверяйте с длиной файла: совпало — это фантом индекса.

`--ignore-cr-at-eol` нужен для серверов, куда код ехал через Windows (весь
репозиторий с CRLF, обычный diff показывает «изменены все 147 файлов»). На
`10.10.42.44` это вылечено 29.07: после `reset --hard` дерево легло по
`.gitattributes` (`.sh/.py/.md/.service` → LF, `.bat/.cmd/.ps1` → CRLF), заодно
вернулся бит `+x` у скриптов, потерянный при переезде.

Только статика (`video_ui/static/*`) — рестарт не нужен, но на киоске обязательна
жёсткая перезагрузка страницы (`Ctrl+Shift+R`): иначе браузер крутит старый JS.

## Много киосков (пилот — 20 точек)

Сервер один, киоски — тонкие клиенты: браузер на `http://СЕРВЕР/?kiosk=1`.
Ставить на них нечего (ни Python, ни venv) — только `deploy/kiosk-start.bat`
и ярлык на него в автозагрузке (`Win+R` → `shell:startup`).

**Файл на всех точках ОДИН И ТОТ ЖЕ**, отличается только `kiosk-id.txt` рядом
с ним — одна строка с названием точки (`astana`, `aktobe`). Оно уезжает в URL
параметром `id=`, оттуда полем `kiosk` в логи сервера и в раздел «По киоскам»
отчёта. Без этого файла точка подпишется именем машины (`%COMPUTERNAME%`,
обычно `WIN-8KJ2…`), и опознать город в отчёте будет нельзя — `.bat` про это
предупреждает в консоли при запуске.

### Рассылка: по архиву на город

Список точек — `deploy/kiosks.txt` (id + человеческое название). Архивы:

```bash
python -m scripts.make_kiosk_bundles --list   # план
python -m scripts.make_kiosk_bundles          # out/kiosk-bundles/*.zip + SEND-LIST.txt
```
В каждом ZIP: `kiosk-start.bat` (байт в байт), `kiosk-id.txt` с id этого города
и `README.txt` с установкой в три шага. `SEND-LIST.txt` — кому какой архив;
при рассылке двадцати адресатам руками перепутать архивы проще простого.

⚠️ **Только латиница в id.** Кириллицу вырезает санитайзер страницы
(`video_ui/static/index.html:262`, набор `[A-Za-z0-9._-]`, 32 символа), и точка
уедет в логи без имени. `make_kiosk_bundles` проверяет это при сборке и на
дубликаты id (две точки слиплись бы в одну строку отчёта).

⚠️ **Проверка `/health` идёт через PowerShell, а не curl.** curl НЕ использует
системный прокси Windows, а браузер использует: в регионе 30.07 Chrome открывал
`http://СЕРВЕР/health` без проблем, а `.bat` вечно висел на строке
`waiting for backend`. Симптом «пинг есть, страница в браузере открывается, а
киоск не стартует» — это он. Проверка обязана ходить тем же путём, что и киоск.
Любой непонятный код возврата (нет PowerShell, запрет политикой) = открываем
браузер, а не отказываемся работать.

⚠️ **Два экземпляра киоска.** `start /wait` ждёт завершения запущенного
`chrome.exe`. Но если браузер с профилем `AidosKiosk` УЖЕ работает, новый процесс
передаёт ему команду и завершается сам — мгновенно. `/wait` тут же возвращается,
скрипт решает «браузер закрыли» и запускает снова: **новое окно каждые 3 секунды**
(жалоба 30.07 — киоск поднялся автозапуском, а `.bat` кликнули руками). Теперь
`.bat` спрашивает PowerShell, не запущен ли киоск, и в этом случае пишет
«already running» и выходит. Проверка стоит и перед первым запуском, и в цикле
перезапуска, плюс стоп после 10 мгновенных выходов подряд (браузер не стартует
вовсе — сломанный флаг, антивирус).
⚠️ Проверка сравнивает код возврата **строго с 1**: `if errorlevel 1` истинно и
для 9009 «команда не найдена», и на машине с заблокированным PowerShell киоск не
запустился бы ВООБЩЕ. При любой непонятной ошибке идём запускать браузер.

⚠️ **Переводы строк.** `.bat` должен доехать до Windows с CRLF (в репозитории
это держит `.gitattributes`, при сборке архива проверяет `check_bat`). Скачаешь
файл кнопкой «Raw» с GitHub — получишь LF, и cmd.exe споткнётся на метках: `The
system cannot find the batch label specified - waitloop`. Поэтому и рассылаем
ZIP, а не `.bat` россыпью: внутри архива байты не меняет ни мессенджер, ни
случайное «сохранить как» в блокноте.

### Пропуск точки и ограничение темпа

Киоск-страница отдаётся всей сети на `:80`, и `?id=` — это подпись, а не пропуск.
Без ключа отключённый регион обходит рубильник, просто убрав `&id=…` из ярлыка,
а любая машина в сети может задавать вопросы за счёт бюджета на облако. Две
дешёвые преграды закрывают оба случая.

**Пропуск.** У каждого региона свой ключ; сервер сверяет имя с ключом. Файл
`kiosks-keys.txt` в корне проекта (строки `<id> <ключ>`), **секрет — в
`.gitignore`**. Генерируется вместе с архивами и обязан лежать в двух местах:
```bash
python -m scripts.make_kiosk_bundles              # выдаст ключи новым точкам
scp kiosks-keys.txt root@10.10.42.44:/root/afm-ai-dos/kiosks-keys.txt
```
⚠️ Ключи **стабильны при пересборке**: существующие берутся из файла, новые
выдаются только новым точкам. Иначе у региона, которому архив уже отправлен,
пропуск разошёлся бы с серверным — а на точке никого нет, кто это заметит.

Проверка **мягкая по умолчанию** (`KIOSK_KEY_REQUIRED=false`): неверный ключ
отвергается всегда, запрос без ключа — пропускается. Так проверку можно
выкатить, не погасив точки, которые ещё не получили архив.

⚠️ **Когда включать строгий режим — смотреть в админке, а не наугад.** В мягком
режиме запрос без ключа проходит МОЛЧА, поэтому в разделе «Киоски» есть колонка
**Пропуск** (есть / НЕТ / не обращалась) и строка-вердикт над таблицей. Пока
там «N точек обращались БЕЗ пропуска», включать нельзя — они получат отказ, и
узнаете вы об этом от регионов по телефону. Когда все 20 переустановлены:
```bash
ssh root@10.10.42.44 "echo 'KIOSK_KEY_REQUIRED=true' >> /root/afm-ai-dos/.env"
ssh root@10.10.42.44 'systemctl restart ai-dos-api'
```

⚠️ Ключ лежит текстом на машине в помещении, куда ходят люди: он закрывает
постороннего в сети, но не того, кто стоит у самого киоска. Нужна настоящая
граница — списки IP на файрволе.

**Темп.** `KIOSK_RATE_PER_MIN` (по умолчанию 10) — сколько вопросов в минуту
принимаем с одной точки, а если она не назвалась — с одного адреса. Отказ `429`
приходит **до** STT/RAG/TTS (замер: 2.5 мс), поэтому шумящий клиент почти ничего
не стоит серверу. Это не то же, что `MAX_CONCURRENT_VOICE`: тот ограничивает
одновременность, но без лимита темпа один клиент держит оба слота бесконечно, и
все 20 городов встают в очередь за ним. `0` выключает ограничение.

Кто шумит:
```bash
ssh root@10.10.42.44 'journalctl -u ai-dos-api --since "1 hour ago" | grep -o "kiosk=[^ ]*" | sort | uniq -c | sort -rn'
ssh root@10.10.42.44 'journalctl -u ai-dos-api --since today | grep -c "превышен темп"'
```

### Админка флота: статус и рубильник в браузере

Страница `http://СЕРВЕР/admin?token=…` — четыре раздела с общим селектором
периода (сутки / 7 / 30) и кнопками «CSV» и «Печать»:

- **Обзор** — вывод словами, плитки тремя группами (сколько спрашивают /
  качество ответов / скорость) со светофором по порогам, график обращений по
  суткам с выделенной долей без ответа, ожидание по стадиям STT/RAG/TTS. Только
  этот раздел уходит на печать: это и есть справка руководству.
  ⚠️ В таблице ожидания вместо «максимума» стоит счётчик **«дольше 20 с»**
  (`ADMIN_SLOW_MS`). Максимум бесполезен с двух сторон: при малом числе замеров
  он РАВЕН p95 (до 11 замеров перцентиль попадает на последний элемент — это
  буквально одно и то же число), а при большом показывает один случайный
  выброс. Счётчик осмыслен и на трёх записях, и на трёх тысячах, и его можно
  прямо назвать в справке: «столько граждан ждали дольше 20 секунд».
- **Киоски** — таблица всех точек из `deploy/kiosks.txt`: на связи или молчит,
  вопросов за период, «нет в базе», ошибок, ожидание; кнопка
  «Отключить/Включить» и общий рубильник «тех. работы». Пишет в тот же
  `kiosks-disabled.txt`, что правят по ssh, — два пути управления одним
  состоянием. Кнопка «Обращения» открывает журнал по этой точке.
- **Обращения** — журнал: время, точка, вопрос (ответ раскрывается по клику),
  результат, ожидание. Фильтры: точка, период, «только нет в базе», «только с
  ошибкой», поиск по тексту; пагинация.
- **Языки** — русский и казахский РЯДОМ, по строкам-показателям. Языки идут
  через разные движки озвучки (F5 на своей GPU против облака ElevenLabs), и в
  общей сводке их задержки складываются в среднее, которого не существует: на
  живых логах медиана русского 4,0 с, казахского 23,1 с — разница в 5,8 раза, и
  ВСЕ случаи «дольше 20 с» казахские. Раздел заканчивается выводом словами.
- **Вопросы** — топ частых и отдельно **топ без ответа в базе**. Второе —
  прямой список на пополнение базы: гражданам эти темы нужны, а Ai-dos о них
  не знает.

⚠️ **Все цифры считает `app/analytics.py`, и ТОТ ЖЕ модуль использует CLI-отчёт**
`scripts.interactions_report`. Поэтому браузер и консоль не могут разойтись —
если правите арифметику, правьте её там, а не в двух местах.

Точка, которая есть в логах, но не в `deploy/kiosks.txt` (переименовали регион,
записи пилота без имени), в таблице всё равно показывается с пометкой «нет в
списке флота»: иначе её история стала бы невидимой.

**Тексты обращений — ПДн.** `ADMIN_LOGS=true` по умолчанию: в журнале видны
вопрос и ответ. Выключается одной строкой в `.env`, и тогда пропадают только
тексты — вся статистика и тайминги остаются:
```bash
ssh root@10.10.42.44 "echo 'ADMIN_LOGS=false' >> /root/afm-ai-dos/.env"
ssh root@10.10.42.44 'systemctl restart ai-dos-api'
```

**CSV** — те же отфильтрованные записи (`/admin/export.csv`), с BOM UTF-8: без
него Excel на Windows покажет кириллицу кракозябрами.

**Три разных исхода, а не «ошибка».** Поле `error` мешает в одну кучу то, на что
надо реагировать по-разному, поэтому и в админке, и в CLI они разделены:
`stt`/`rag`/`tts` — **сбой** (упал сервис, надо чинить); `empty`/`noise` — **не
расслышал** (тишина или шум у киоска, гражданин просто повторит); `disabled`/`gate`
— **отказано** (сработал рубильник или пропуск, то есть наши же настройки).
Считать отказы ошибками значит раздувать долю сбоев и прятать реальные поломки.

⚠️ **`noise` важен для отчёта о базе.** Раньше отсеянный шум помечался
`answer_found=false`, то есть попадал и в долю «нет в базе», и в список «чем
пополнять базу». На живой странице 30.07 это дало 66,7% «пробелов», из которых
настоящих не было ни одного: там сидели артефакт STT «Продолжение следует.» и
казахская петля. Теперь базу такие записи не трогают вовсе.

### Очистить журнал обращений (тестовые данные)

⚠️ **Просто `rm` НЕЛЬЗЯ.** Аналитику пишет `TimedRotatingFileHandler`, который
держит файл открытым: после удаления он продолжит писать в отвязанный inode, и
новые обращения будут исчезать молча. Файлы убираем и **перезапускаем `api`**:

```bash
ssh root@10.10.42.44 'bash -s' <<'EOF'
cd /root/afm-ai-dos
ARCH=/root/ai-dos-logs-$(date +%F-%H%M)
mkdir -p "$ARCH"
mv logs/interactions.jsonl* "$ARCH"/ 2>/dev/null
systemctl restart ai-dos-api
sleep 3
echo "архив: $ARCH ($(ls -1 "$ARCH" | wc -l) файлов)"
echo "logs:  $(ls -1 logs/ 2>/dev/null | wc -l) файлов"
systemctl is-active ai-dos-api
EOF
```
Архив лежит ВНЕ проекта — `git reset --hard` при обновлении его не тронет.
Убедились, что старые цифры не нужны, — `rm -rf /root/ai-dos-logs-*`.

Токен задаётся в `.env` проекта и **по умолчанию пуст = админки нет вовсе**
(`404`, а не `401`: не подсказываем, что тут есть что открывать):
```bash
ssh root@10.10.42.44 "echo 'ADMIN_TOKEN=$(openssl rand -hex 16)' >> /root/afm-ai-dos/.env"
ssh root@10.10.42.44 'systemctl restart ai-dos-api && grep ADMIN_TOKEN /root/afm-ai-dos/.env'
```
⚠️ **Ссылка с токеном = пароль.** Киоск-страница отдаётся всей сети на `:80`, и
адрес админки видят те же 20 регионов. Пересылать её можно только тем, кому
можно гасить точки; смена — новый токен в `.env` + рестарт `ai-dos-api`.

**Статус берётся из heartbeat:** страница киоска раз в `KIOSK_PING_SECONDS`
(60 с) стучится в `/kiosk/ping`, сервер запоминает время и в ответ сообщает
точке, не отключили ли её — поэтому отключённый киоск показывает сообщение
**до** того, как гражданин заговорит, а не после. Молчание дольше
`KIOSK_OFFLINE_AFTER_S` (300 с) красит точку в «не на связи».

⚠️ Heartbeat живёт в памяти процесса: после `systemctl restart ai-dos-api` все
точки минуту показываются молчащими, пока не придут пинги. Это не сбой.

### Отключить отдельную точку (или все сразу)

Регион не готов, идёт ремонт, точку нужно временно погасить — а физически до неё
другой город. Список отключённых лежит на сервере файлом
`/root/afm-ai-dos/kiosks-disabled.txt` и перечитывается по времени изменения,
поэтому **перезапускать ничего не нужно**:

```bash
ssh root@10.10.42.44 'cat >> /root/afm-ai-dos/kiosks-disabled.txt' <<'EOF'
turkestan   Киоск на ремонте до 5 августа
zhetysu
EOF
```
Текст после id — то, что увидит гражданин на экране (без текста берётся
«Сервис временно недоступен. Приносим извинения.»). Строка с `#` в начале
выключена — так точку возвращают в работу. Особый id `*` гасит **все** точки
разом, это окно обслуживания.

Отключённый киоск разворачивается **до** STT/RAG/TTS: за облако не платим и слот
семафора не занимаем. Обращение при этом всё равно пишется в аналитику с
`error=disabled` — видно, что у погашенной точки продолжают стоять люди.

⚠️ Файл в `.gitignore` намеренно: это оперативное состояние, а не код. Иначе
`git reset --hard` при обновлении молча включил бы обратно регионы на ремонте.

⚠️ **Это рубильник эксплуатационный, не защита доступа.** Номер точки приходит
от браузера (`?id=` в адресе) и подделывается тривиально: выключить свой киоск
он позволяет, закрыть доступ чужому — нет. Для настоящей границы нужны списки
IP или токен на точку.

**Перед раскаткой по филиалам** проверь с самой киоск-машины, что сервер виден
из её сети (это WAN, а не соседняя розетка):
```cmd
ping СЕРВЕР
curl http://СЕРВЕР/health
```

**Ёмкость.** Все точки бьют в один бэкенд, и одновременных обращений он
обслуживает `MAX_CONCURRENT_VOICE` (дефолт **2**, [app/config.py](app/config.py)) —
семафор охватывает весь путь STT→RAG→TTS, остальные ждут очереди. Ориентир по
логам: русский ответ ~2-4 с, казахский на Spark ~13 с. При 1-3 одновременных
говорящих дефолта хватает; прежде чем поднимать лимит — замерь, сколько
параллельных запросов держит TTS-нода (её и защищает семафор).

**Кто и как работает — по точкам:**
```bash
.venv/bin/python -m scripts.interactions_report --dir logs --days 7
```
Раздел «По киоскам» покажет по строке на точку: обращений, доля «нет в базе»,
ошибки, медиана полного цикла. Точка без обращений за сутки — повод сходить
посмотреть, жив ли экран; аномальная доля «нет в базе» на одной точке при
нормальной на других — обычно микрофон (шум, не тот вход по умолчанию).
В journald тот же номер: `journalctl -u ai-dos-api | grep 'kiosk=astana-01'`.

## Логи и аналитика

Два независимых потока (реализация — `app/logging_setup.py`):

- **Ops (ошибки, тайминги, request-id)** — в stderr → **journald**. Смотреть как обычно:
  ```bash
  journalctl -u ai-dos-api -f                    # живой поток
  journalctl -u ai-dos-api | grep interaction    # строки по каждому /voice
  ```
  Пример строки: `interaction kiosk=astana-01 lang=ru stt=320ms rag=1450ms tts=2100ms total=3.9s found=True suggest=0 print=fl provider=f5 error=-` (`kiosk=-`, если точка не прислала номер). Ротацию journald держит сам (`SystemMaxUse` в `journald.conf`).
- **Аналитика — по строке JSONL на каждый `/voice`** в `logs/interactions.jsonl` (суточная ротация, `backupCount=LOG_RETENTION_DAYS` → старые файлы **сами удаляются = ретеншен**). Поля: `kiosk` (номер точки), `question`, `answer`, `lang`, `answer_found`, `suggested`, `print_ids`, `provider`, тайминги стадий, `error`.

⚠️ **`logs/` содержит ПДн граждан** — в git не коммитится (`.gitignore`), с сервера наружу не выносить без согласования.

**Отчёт для АФМ** (спрос, доля fallback = дыры в базе, p50/p95 задержек, ru/kk):
```bash
.venv/bin/python -m scripts.interactions_report --dir logs           # всё
.venv/bin/python -m scripts.interactions_report --dir logs --days 7  # за неделю
```

**Настройки** (env / `.env`, дефолты рабочие — менять не обязательно):

| Переменная | Дефолт | Смысл |
|---|---|---|
| `LOG_LEVEL` | `INFO` | уровень ops-логов |
| `LOG_DIR` | `logs` | куда писать JSONL (относит. WorkingDirectory) |
| `LOG_ANALYTICS` | `true` | писать JSONL по `/voice` |
| `LOG_QUESTIONS` | `full` | текст вопроса: `full` / `hash` (sha256) / `off` |
| `LOG_ANSWERS` | `true` | писать текст ответа |
| `LOG_RETENTION_DAYS` | `30` | сколько суток хранить (= число суточных файлов) |

**systemd:** journald ловит stdout сам; `logs/` под `/opt/ai-dos` при текущем `ProtectSystem=full` пишется без доп. настроек. Если ужесточишь до `ProtectSystem=strict` — добавь в юнит `ReadWritePaths=/opt/ai-dos/logs`.
