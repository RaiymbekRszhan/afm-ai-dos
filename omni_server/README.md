# KazakhTTS-OmniVoice — сервер казахского TTS

Отдельный сервис казахского синтеза: [`shyngys879/KazakhTTS-OmniVoice`](https://huggingface.co/shyngys879/KazakhTTS-OmniVoice)
— файнтюн `k2-fsa/OmniVoice` на ISSAI KazakhTTS2. Пришёл на смену Spark: офлайн,
бесплатно и без стохастических отказов. Основной API зовёт его по HTTP.

```
Основной API  ──HTTP──▶  OmniVoice-сервер (этот)  ──▶  KazakhTTS-OmniVoice
   POST /tts {"text","language"}                       возвращает WAV
```

Контракт **совпадает со Spark намеренно**: смена движка = две строки в `.env`
(`TTS_KK_PROVIDER` + `OMNI_URL`), нарезка/склейка/стриминг/фолбэк в оркестраторе
не меняются вообще.

> ⚠️ **На бою этот сервер НЕ запущен.** На GPU-ноде АФМ (`192.168.165.2:8992`,
> `cuda:7`) с 2026-08-17 крутится ЧУЖАЯ обёртка вокруг той же модели —
> «KazakhTTS API», её ставили админы ноды НА МЕСТО Spark. Контракт у неё
> совпадает с нашим (`POST /tts {text, language}` → `audio/wav`, 24 кГц моно
> 16 бит), поэтому оркестратору всё равно, кто отвечает; проверено 17.08.
> Замер там же: 222 симв. → 14,3 с звука за **1,2 с**, короткий кусок — 0,8 с.
> Всё, что ниже, нужно для ЛОКАЛЬНОГО запуска и для развёртывания на своей
> Windows/Linux-машине, если ноду придётся дублировать.

## ⚠️ Голос на ноде АФМ: включить клон (нужно админам ноды)

Замер 17.08 показал, что обёртка на `192.168.165.2:8992` зовёт `generate()` БЕЗ
референса, то есть модель выбирает голос сама. Получается женский голос ~219 Гц,
тогда как русский (F5) говорит мужским 147 Гц — один «цифровой офицер» меняет
пол вместе с языком.

Два способа получить голос АФМ на казахском — выбирать по тому, есть ли доступ к
коду обёртки на ноде.

### Способ 1: наш сервер + клиентский референс (как у F5, доступа к ноде не надо)

Поднять `omni_server` на любой CUDA-машине (на ноде вторым портом, на
Windows-машине — см. разделы ниже) и включить в `.env` оркестратора:
```
OMNI_URL=http://<машина>:8993/tts
OMNI_REF_AUDIO=refs/ref_kk_omni.wav
OMNI_REF_TEXT=@refs/ref_kk_omni.txt
```
Дальше образец едет в КАЖДОМ запросе (`multipart {ref_audio, ref_text, gen_text}`)
— ровно так оркестратор задаёт голос русского F5 на `:8991`. Сервер кэширует
клон-промпт по хешу образца, поэтому токенизация случается один раз, а не на
каждый кусок ответа (замер на Маке: первый запрос 9,1 с, второй 5,9 с).
⚠️ `OMNI_REF_AUDIO` работает ТОЛЬКО с этим сервером: чужая обёртка на ноде на
multipart отвечает 422, а референс внутри JSON молча игнорирует.

### Способ 2: правка их обёртки (если доступ к коду ноды есть)

Три строки. Файлы образца — в этом репозитории: `refs/ref_kk_omni.wav`
(24 кГц моно, 10,7 с) + `refs/ref_kk_omni.txt` (транскрипт).

```python
# рядом с загрузкой модели, ОДИН раз при старте:
_PROMPT = model.create_voice_clone_prompt(
    "ref/Clone.wav",
    ref_text=open("ref/Clone.txt", encoding="utf-8").read().strip(),
)

# в обработчике /tts — добавить один аргумент:
audio = model.generate(text=req.text, language="Kazakh",
                       voice_clone_prompt=_PROMPT)   # <-- было без него
```

⚠️ **Промпт считать на СТАРТЕ, а не в обработчике.** Вариант «передавать
`ref_audio=`/`ref_text=` в каждый `generate()`» тоже работает (так написан
пробный скрипт на Маке), но тогда образец токенизируется на КАЖДЫЙ кусок ответа
— а ответ гражданину режется на 3-5 кусков. На Маке эта токенизация стоила 2,5 с.

⚠️ Транскрипт обязан ТОЧНО совпадать со сказанным в WAV, иначе клон плывёт —
поэтому текст возим файлом, а не строкой в коде через терминалы.

Приёмка — по высоте голоса, а не на слух: после перезапуска медиана F0 у выдачи
должна упасть с ~219 Гц до ~150 Гц (как у образца).

## Чем лучше Spark

| | Spark-TTS-Kazakh | **OmniVoice** |
|---|---|---|
| Тип модели | авторегрессивная LLM | маскированное декодирование за `num_step` шагов |
| Отказы | вырожденная генерация (0 токенов) → `422`, лечится 6 попытками | этого класса отказов нет |
| Время от длины | **квадратично** (100 симв. → 18 c, 330 → 117 c) | ≈ линейно от длительности звука |
| Темп речи | `SPARK_SPEED` крутить НЕЛЬЗЯ (ронял синтез) | `OMNI_SPEED` — обычный множитель |
| Клон голоса | пришлось выключить ради стабильности | считается один раз на старте, дальше бесплатен |

## Установка (там, где есть интернет)

```bash
bash omni_server/setup.sh    # .venv-omni + библиотека + модель (~3 ГБ)
bash omni_server/run.sh      # слушает 8811 (локально)
```
Проверка:
```bash
curl -X POST http://localhost:8811/tts \
  -H 'Content-Type: application/json' \
  -d '{"text":"Сәлеметсіз бе!","language":"kazakh"}' --output test.wav
```

⚠️ **Отдельный venv обязателен.** `omnivoice` требует `transformers >= 5.3`, а
Spark сидит на 4.46 — в один venv они не сойдутся, как и с основным `.venv`.

⚠️ **Аудио-токенизатор — ВТОРАЯ модель.** `OmniVoice.from_pretrained` тянет
`eustlb/higgs-audio-v2-tokenizer` (768 МБ), если рядом с чекпоинтом нет папки
`audio_tokenizer/`. `setup.sh` кладёт её сразу — иначе сервис под
`HF_HUB_OFFLINE=1` не стартует вовсе.

## Развёртывание на WINDOWS-машине с видеокартой, порт 8993

Здесь всё, что нужно, по шагам. Оркестратор (`10.10.42.44`) будет ходить на эту
машину по `http://<её IP>:8993/tts`.

### Шаг 0. Что должно быть на машине

| Проверить | Как | Если нет |
|---|---|---|
| Видеокарта NVIDIA | `nvidia-smi` в cmd | без CUDA синтез в десятки раз медленнее — для киоска не годится |
| Python 3.11 или 3.12 | `py -0p` | поставить с python.org, галочка «Add python.exe to PATH». ⚠️ Не 3.13: колёса есть не у всех зависимостей |
| ~10 ГБ на диске | | модель 2,3 ГБ + токенизатор 768 МБ + torch с CUDA ~3 ГБ |
| Постоянный IP | `ipconfig` | по DHCP адрес сменится — и казахский молча уедет в фолбэк |
| Машина видна с сервера | с `10.10.42.44`: `ping <IP>` | без этого дальше идти бессмысленно |

Запиши IP — он понадобится на шаге 6.

### Шаг 1. Код проекта на машину

Нужны только `omni_server\`, `refs\` и место под `models\`. Проще всего целиком:
```cmd
git clone https://github.com/RaiymbekRszhan/afm-ai-dos.git C:\ai-dos
cd /d C:\ai-dos
```
Если git недоступен — скачай ZIP репозитория и распакуй в `C:\ai-dos`
(⚠️ путь без пробелов и кириллицы).

### Шаг 2. Установка

**Если на машине есть интернет** — одной командой:
```cmd
omni_server\setup.bat
```
Он создаёт `.venv-omni`, ставит **torch с CUDA** (это главное отличие от Linux:
обычный `pip install torch` на Windows тянет сборку БЕЗ видеокарты), затем
`omnivoice`, затем качает обе модели.

**Если интернета нет** — вези с Мака готовые модели:
```bash
# на Маке, из корня проекта
bash omni_server/bundle.sh          # -> out/omni-models.tar.gz (~3 ГБ)
```
Скопируй файл на Windows-машину (флешка/шара), там:
```cmd
mkdir C:\ai-dos\models
tar -xzf C:\путь\omni-models.tar.gz -C C:\ai-dos\models
```
(`tar` встроен в Windows 10/11, ставить нечего.) Колёса тогда придётся принести
так же — `pip download` на машине с интернетом и тем же Python, потом
`pip install --no-index --find-links=<папка>`.

### Шаг 3. Убедиться, что видна видеокарта

```cmd
.venv-omni\Scripts\python -c "import torch;print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"
```
Должно быть `True` и название карты. `False` = поставился CPU-torch: переставить
с индекса PyTorch (`TORCH_INDEX` в `setup.bat`; для старых драйверов `cu121`
вместо `cu124`, версию CUDA показывает `nvidia-smi` в правом верхнем углу).

### Шаг 4. Первый запуск руками

```cmd
omni_server\run.bat
```
Первый старт грузит модель (~30–60 с) и считает клон-промпт. Когда появится
`Uvicorn running on http://0.0.0.0:8993`, в ДРУГОМ окне cmd:
```cmd
curl http://localhost:8993/health
```
Ждём `{"status":"ok",...,"cloning":true,...}` — `cloning:true` значит образец
голоса подхватился.

### Шаг 5. Замер — главный шаг, не пропускать

```cmd
curl -X POST http://localhost:8993/tts -H "Content-Type: application/json" ^
  -d "{\"text\":\"Karzhy monitoringi subektileri kudikti operatsiyalar turaly habarlama beruge mindetti.\",\"language\":\"kazakh\"}" ^
  --output C:\temp\kk.wav
```
(латиница в примере — чтобы cmd не испортил кириллицу; на качество это не
влияет, важна ДЛИНА). В окне сервиса появится строка вида
`[omni] 210 симв. -> 11.0 c звука за 2.3 c`.

Смотреть надо на последнее число. Оркестратор шлёт куски по ~260 символов:

| Время на кусок | Вывод |
|---|---|
| до ~2 с | отлично, ставим как есть |
| 2–4 с | приемлемо, но снизь `OMNI_NUM_STEP` до 16 и сравни на слух |
| больше 4 с | `OMNI_NUM_STEP=16`, снова замер; не помогло — машина для этого слаба |

Открой `C:\temp\kk.wav` и послушай — это ровно тот голос, который услышит
гражданин.

### Шаг 6. Автозапуск и брандмауэр

Правой кнопкой → «Запуск от имени администратора»:
```cmd
omni_server\install-autostart.bat
```
Он ставит задачу планировщика **при старте системы от имени SYSTEM** (не в
«Автозагрузку»: та ждёт входа пользователя, и после перезагрузки сервис молчал бы
до логина), открывает порт 8993 только для локальной сети и гасит засыпание
машины. Лог сервиса пойдёт в `logs\omni.log`.

```cmd
schtasks /Run /TN "AiDosOmniTTS"          REM запустить сейчас
schtasks /Query /TN "AiDosOmniTTS"        REM статус
```
Проверь с сервера, что снаружи достучаться можно:
```bash
ssh root@10.10.42.44 'curl -s -m 5 http://<IP машины>:8993/health'
```
Молчит — брандмауэр или сеть, а не сервис.

### Шаг 7. Переключить оркестратор

На `10.10.42.44` в `.env` проекта:
```
TTS_KK_PROVIDER=omni
OMNI_URL=http://<IP машины>:8993/tts
TTS_KK_FALLBACK=eleven
```
```bash
systemctl restart ai-dos-api
curl -s localhost:8000/health | grep -o '"omni":[^}]*}'
bash scripts/healthcheck.sh UI=http://localhost
```
Задай киоску казахский вопрос и послушай. В админке (`/admin?token=…`) в поле
`provider` у казахских обращений должно стоять `omni` — если там `eleven`,
значит сработал фолбэк и OmniVoice недоступен.

**Откат** — вернуть `TTS_KK_PROVIDER=eleven` и перезапустить `ai-dos-api`.
Одна строка, ничего переустанавливать не нужно.

### Чем Windows отличается — короткий список граблей

1. **`pip install torch` даёт сборку БЕЗ CUDA.** На Linux дефолтное колесо
   уже с CUDA, на Windows — нет. Всегда проверять `torch.cuda.is_available()`.
2. **Кириллица в переменных окружения.** `cmd.exe` корёжит её по локали консоли,
   а транскрипт образца обязан совпадать со сказанным в WAV. Поэтому
   `OMNI_SPEAKER_TEXT` задаётся как `@путь\к\файлу` — сервер читает его в UTF-8.
3. **Машина уснёт — казахский пропадёт на всех 20 точках.** `install-autostart.bat`
   гасит сон, но если машину кто-то «усыпит» руками, лечится только пробуждением.
4. **Автозагрузка ≠ автозапуск.** Папка «Автозагрузка» срабатывает при входе
   пользователя; нужна задача планировщика с триггером «При запуске системы».
5. **IP по DHCP.** Смена адреса = молчащий казахский. Просить у IT статику или
   резервирование по MAC.

## Развёртывание на Linux GPU-ноде АФМ (192.168.165.2) — замена Spark

Spark живёт там же на `:8992`. Ставим OmniVoice **на соседний порт `:8993`**, а
не поверх: пока идёт сравнение, оба движка живы, и откат — это одна строка в
`.env` оркестратора, без переустановки.

### 1. Модель и колёса на ноду (интернета у неё нет)

Модель уже скачана на Маке (её тянул тестовый скрипт), поэтому берём оттуда:
```bash
# на Маке, из корня проекта
bash omni_server/bundle.sh                  # -> out/omni-models.tar.gz (~3 ГБ)
scp out/omni-models.tar.gz gpu@192.168.165.2:/tmp/
```
Колёса (`omnivoice`, `torch`, `transformers`) зависят от питона и архитектуры
ноды, поэтому качаем их **на машине с той же ОС**, у которой есть интернет —
проще всего на боевом сервере (`10.10.42.44`, у него интернет через прокси АФМ):
```bash
# на 10.10.42.44 — ВАЖНО: тот же python3.X, что на GPU-ноде
python3 -m venv /tmp/dl && /tmp/dl/bin/pip install --upgrade pip
/tmp/dl/bin/pip download -d /tmp/omni-wheels \
  omnivoice==0.2.1 soundfile fastapi "uvicorn[standard]" pydantic
tar -czf /tmp/omni-wheels.tar.gz -C /tmp omni-wheels
scp /tmp/omni-wheels.tar.gz gpu@192.168.165.2:/tmp/
```
Если у самой GPU-ноды интернет ЕСТЬ — оба шага не нужны, просто
`bash omni_server/setup.sh` на ней.

### 2. Установка на ноде

```bash
cd /opt/ai-dos            # каталог проекта на GPU-ноде (там же, где spark_server)
git fetch && git reset --hard origin/main     # или доставить omni_server/ снапшотом

python3 -m venv .venv-omni
source .venv-omni/bin/activate
pip install --upgrade pip
tar -xzf /tmp/omni-wheels.tar.gz -C /tmp
pip install --no-index --find-links=/tmp/omni-wheels \
  omnivoice==0.2.1 soundfile fastapi "uvicorn[standard]" pydantic

mkdir -p models && tar -xzf /tmp/omni-models.tar.gz -C models
ls models/omnivoice-kazakh/model.safetensors models/omnivoice-kazakh/audio_tokenizer
```

### 3. Проверка руками, до systemd

```bash
OMNI_DEVICE=cuda OMNI_PORT=8993 OMNI_HOST=0.0.0.0 bash omni_server/run.sh
# в другом окне:
curl -s localhost:8993/health          # ждём {"status":"ok","cloning":true,...}
time curl -s -X POST localhost:8993/tts -H 'Content-Type: application/json' \
  -d '{"text":"Қаржы мониторингі субъектілері күдікті операциялар туралы хабарлама беруге міндетті.","language":"kazakh"}' \
  --output /tmp/kk.wav
```
**Смотреть надо на время.** В логе сервиса каждая генерация печатает
`N симв. -> M c звука за T c`. Куски к нему приходят по ~260 символов
(`TTS_KK_MAX_CHARS`); если `T` на таком куске больше ~4 с, потоковая озвучка на
казахском станет заметно медленнее нынешнего облака — тогда крутить
`OMNI_NUM_STEP` (32 → 16) и мерить снова.

### 4. Юнит

```bash
cp deploy/ai-dos-omni.service /etc/systemd/system/   # выправить WorkingDirectory/User под ноду
systemctl daemon-reload
systemctl enable --now ai-dos-omni
journalctl -u ai-dos-omni -f
```

### 5. Переключение оркестратора (на 10.10.42.44)

В `.env` проекта:
```
TTS_KK_PROVIDER=omni
OMNI_URL=http://192.168.165.2:8993/tts
TTS_KK_FALLBACK=eleven          # облако осталось страховкой
```
```bash
systemctl restart ai-dos-api
curl -s localhost:8000/health | python3 -m json.tool | grep -A4 omni
bash scripts/healthcheck.sh UI=http://localhost
```
Откат — вернуть `TTS_KK_PROVIDER=eleven` (или `spark`) и перезапустить api.
Spark глушим только после того, как OmniVoice отработал несколько дней:
`systemctl disable --now ai-dos-spark` на ноде.

## Голос

- **Клонирование** (по умолчанию): `OMNI_SPEAKER_WAV` + `OMNI_SPEAKER_TEXT`.
  В репозитории лежит `refs/ref_kk_omni.wav` — образец голоса АФМ, 24 кГц моно.
  ⚠️ `OMNI_SPEAKER_TEXT` обязан ТОЧНО совпадать с тем, что произносится в файле,
  иначе клон плывёт; текст — в `refs/ref_kk_omni.txt`.
  На первом старте рядом с WAV появится `.omni.pt` — готовый промпт; укажи его в
  `OMNI_PROMPT`, и следующий старт не будет пересчитывать.
- **Voice design** без образца: `OMNI_INSTRUCT="A calm middle-aged male voice"`
  (модель обучена на категориях gender × age × pitch, см. её карточку).
- Текущий режим видно в `/health` → `"cloning": true|false`.

## Ручки скорости

| Ручка | Что делает | Замечание |
|---|---|---|
| `OMNI_NUM_STEP` (32) | шагов декодирования | главный рычаг «быстрее/грязнее»; мерить на слух |
| `OMNI_SPEED` (0 = авто) | множитель темпа | в отличие от `SPARK_SPEED` крутить можно |
| `OMNI_GUIDANCE` (2.0) | сила следования тексту | ниже — свободнее интонация, выше — чётче дикция |

Общий разгон речи всё равно держим на плеере (`SPEECH_RATE` в
`video_ui/static/index.html`): звук уже готов, ускорение ничего не стоит и не
может уронить синтез.

⚠️ Паузы на стыке кусков: OmniVoice сам добавляет по 100 мс тишины с каждой
стороны, а оркестратор кладёт сверху `TTS_GAP_MS` (300/150 мс). Если на слух
между предложениями провисает — уменьшать `TTS_GAP_MS`, а не трогать модель.

## Замер на Маке (MPS, fp16, 2026-08-17) — почему нужен GPU и как читать цифры

| `OMNI_NUM_STEP` | 35 симв. (2,1 с звука) | 210 симв. (11,0 с звука) |
|---|---|---|
| 32 (дефолт) | 19,9 с | 34,2 с |
| 16 | 9,6 с | 17,3 с |
| 8 | 4,9 с | 8,9 с |

Читается так: **время ровно пропорционально `num_step`** (32 → 16 → 8 делит его
вдвое каждый раз) и лишь слабо зависит от длины текста. Значит на кусок уходит
`num_step × (накладные на шаг + немного от длины)`, и на MPS накладные на шаг
чудовищные (~0,5 с) — короткий кусок в 2 секунды звука синтезируется 20 секунд.
Это болезнь MPS, а не модели: на CUDA накладные на шаг измеряются миллисекундами,
поэтому на GPU-ноде ждём единиц секунд при тех же 32 шагах.

Вывод: **на Маке движок гонять нельзя** (только проверка контракта), а решение о
переключении флота принимаем по замеру на GPU-ноде АФМ. Если и там не уложится —
первым делом крутить `OMNI_NUM_STEP` (16 — почти всегда неотличимо на слух,
8 — уже слышно), а не резать текст мельче.
