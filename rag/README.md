# RAG для цифрового офицера АФМ «Ai-dos»

Аватар принимает вопрос голосом и отвечает голосом, **строго по базе** (кодексы РК,
Закон о ПОД/ФТ, рекомендации ФАТФ, справка АФМ). Главная задача — **не выдумывать**.

```
микрофон → STT → POST /ask → [ RAG: поиск по базе → LLM(вопрос + найденные нормы) ] → текст → TTS → динамик
                  └──────────────── этот репозиторий ────────────────┘
```

STT/TTS/embedding у вас уже настроены. Здесь — слой RAG поверх вашей LLM.

---

## Что такое LightRAG (коротко, по делу)

Это не «дообучение». Модель ничего не учит. LightRAG делает две вещи:

1. **При загрузке** режет документы на куски и считает эмбеддинги (ваш `qwen3-embedding-8b`).
2. **При вопросе** находит релевантные куски по смыслу (вектор), складывает их в
   «Контекст» и отдаёт LLM с жёсткой инструкцией: *отвечай только по этому контексту*.

Тот сниппет `vllm_embedding_func`, что вам дали, — это и есть «функция эмбеддинга»
для LightRAG. Здесь она уже корректно подключена (`ragsvc/providers.py`).

**Только векторный поиск (граф знаний не используем).** LightRAG умеет строить граф
сущностей, но при загрузке это дёргает LLM на **каждый** чанк — на сети АФМ проверено:
LLM-сервер упирается в таймауты (часы, потеря кусков). Поэтому граф отключён, используется
только векторный поиск: индексация зовёт лишь эмбеддинги (минуты), качество подтверждено
тест-набором (24/24, см. `eval/`). Для типичных вопросов гражданина вектора достаточно.

## Установка

```bash
uv venv .venv && source .venv/bin/activate     # без uv: python3 -m venv .venv && source .venv/bin/activate
uv pip install -r requirements.txt             # без uv: pip install -r requirements.txt
cp .env.example .env        # затем заполни .env
```
> Версия LightRAG закреплена: `lightrag-hku==1.4.9.10` (в `requirements.txt` и `pyproject.toml`).

В `.env` обязательно укажи **LLM_MODEL** и **LLM_BASE_URL** (узнай у команды — это
генеративная модель на вашем сервере, отдельная от эмбеддингов).

## Шаг 1. Проверка связи и размерности эмбеддинга

```bash
python -m scripts.check
```

Скрипт скажет реальную размерность `qwen3-embedding-8b` — **впиши её в `EMBEDDING_DIM`**.
(если размерность в базе и в конфиге разойдутся — поиск работать не будет).
Для `qwen3-embedding-8b` это **4096** (уже стоит дефолтом в `.env.example`; подтверждено
сервером АФМ).

> Примечание: `providers._embed` вызывает `openai_embed.func(...)`, а не сам
> `openai_embed` — последний задекорирован в LightRAG под OpenAI `text-embedding-3-small`
> (хардкод `embedding_dim=1536`) и иначе падал бы с «dimension mismatch 4096 vs 1536».
> Размерность валидирует наш `EmbeddingFunc(embedding_dim=EMBEDDING_DIM)`.

## Шаг 2. Загрузка базы

Положи документы в `data/` в формате `.md`/`.txt`. В начале каждого файла — метаданные:

```
# LAW: Уголовно-процессуальный кодекс РК
# SHORT: УПК РК
# TYPE: code        ← code | faq | reference
# LANG: ru          ← ru | kk
```

- `TYPE: code` — текст режется **по статьям** («Статья N» или «N-бап»). Цитата в ответе
  будет вида «согласно статье 67 УПК РК».
- `TYPE: faq` — пары вопрос/ответ, разделённые строкой `===`.
- `TYPE: reference` — справка, режется по абзацам.

```bash
python -m ragsvc.ingest            # загрузить всё из data/
```

В репозитории уже лежат рабочие образцы (FAQ, справка, выдержки Закона о ПОД/ФТ) —
можно сразу прогнать и проверить.

## Шаг 3. Запуск сервиса

```bash
export TIKTOKEN_CACHE_DIR="$PWD/vendor/tiktoken"   # словарь токенизатора — офлайн
uvicorn ragsvc.server:app --host 0.0.0.0 --port 8077
```

> ⚠️ **Без `TIKTOKEN_CACHE_DIR` сервис в офлайн-сети не стартует**: LightRAG на старте
> берёт словарь tiktoken, и без локального кэша тот лезет в интернет
> (`openaipublic.blob...`, симптом — `NameResolutionError ... o200k_base.tiktoken`).
> Словари завендорены в `vendor/tiktoken/` (o200k + cl100k) — папка обязана ехать на
> сервер вместе с проектом. Пересоздать (на машине с интернетом):
> `TIKTOKEN_CACHE_DIR=$PWD/vendor/tiktoken python -c "import tiktoken; tiktoken.get_encoding('o200k_base'); tiktoken.get_encoding('cl100k_base')"`.
> `run_api.sh` в корне и `deploy/ai-dos-rag.service` выставляют переменную сами.

Бэкенд аватара после STT шлёт:

```bash
curl -X POST http://localhost:8077/ask \
  -H "Content-Type: application/json" \
  -d '{"question":"Какой порог по операциям с ювелирными изделиями?","lang":"ru"}'
```

Ответ — чистый текст для TTS:
> Купля-продажа ювелирных изделий подлежит финансовому мониторингу при сумме от пяти
> миллионов тенге, согласно статье 4 Закона о ПОД/ФТ.

`lang` — это язык кнопки на экране («қазақша» / «русский»). Модель и так отвечает на
языке вопроса, но `lang` помогает на коротких/смешанных фразах.

## Как мы заставляем его «не врать»

Это не одна галочка, а несколько слоёв (`ragsvc/prompts.py`, `ragsvc/rag_engine.py`):

1. **Нарезка по статьям** — поиск попадает в конкретную норму, а не в обрывок.
2. **Жёсткий системный промпт** — отвечать только по «Контексту», запрет придумывать
   номера статей, суммы, сроки, телефоны. Если ответа в базе нет — фиксированная фраза
   с переадресацией на call-центр 1458 / e-Otinish, **без догадок**.
3. **`temperature=0`** у LLM — меньше «фантазии».
4. **Цитата источника** в каждом ответе (метка статьи едет в `file_paths` и
   возвращается как название документа) — гражданин и проверяющий могут свериться.
5. **Голосовой формат** — промпт убирает markdown и секцию ссылок, чтобы TTS читал гладко.

## Что стоит добавить (по приоритету)

- **Reranker** (`bge-reranker-v2-m3`): на юридических текстах заметно поднимает точность.
  Подними эндпоинт, в `.env` поставь `RERANK_ENABLED=1` — заглушка уже готова
  (`providers.rerank_func`).
- **Версионирование**: законы меняются. Храни дату редакции в `# LAW:` и обновляй базу
  (повторная загрузка по `uid` не плодит дубликаты). Ответ по устаревшей редакции — ошибка.
- **Тестовый набор** «вопрос → правильная статья» — **готов** (`eval/`, 24 кейса ru+kk:
  факты, цитаты, антивыдумка; запуск `python -m eval.run_eval`). Пополняй реальными
  вопросами call-центра 1458.

## Казахский язык

`qwen3-embedding-8b` многоязычный, но казахский — low-resource. **Обязательно** прогони
свой тестовый набор на казахских вопросах и сравни попадание retrieval с русскими.
Это главный технический риск проекта. Граф не используется — поиск только векторный,
эмбеддинги многоязычны (русский и казахский равноправны).

## Структура

```
ragsvc/
  config.py      — конфиг из .env
  providers.py   — адаптеры к вашему vLLM (LLM, embedding, reranker)
  chunking.py    — нарезка по статьям / FAQ / абзацам
  prompts.py     — антигаллюцинационный системный промпт (под TTS)
  ingest.py      — загрузка базы в LightRAG
  rag_engine.py  — сборка RAG + answer()/get_sources()
  server.py      — FastAPI /ask для аватара
scripts/check.py — проверка эндпоинтов и размерности эмбеддинга
data/            — база знаний (образцы внутри)
```
