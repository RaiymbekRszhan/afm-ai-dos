# Оценка качества ответов RAG

Без измерения нельзя улучшать ответы — каждая правка промпта или ретривала
превращается в гадание. Этот набор меряет три вещи, критичные для госюр-ассистента:

1. **Цитирование** — ссылается ли ответ на нужную норму (`expect_source`).
2. **Факты** — есть ли в ответе ключевые значения (`expect_contains`).
3. **Антивыдумка** — на вопросах ВНЕ базы должен сработать отказ «нет информации → 1458»
   (`expect_fallback`), а не выдуманный ответ.

## Запуск
RAG-сервис должен быть поднят (нужен доступ к LLM/эмбеддингам АФМ — сеть по кабелю):
```bash
cd rag && source .venv/bin/activate
# в одном окне — сервис:
uvicorn ragsvc.server:app --host 0.0.0.0 --port 8077
# в другом — оценка:
python -m eval.run_eval
```
Выводит по каждому кейсу `OK / FAIL / ERR` и итог `N/M прошло` (exit code 0 — всё прошло).

## Как пополнять набор
Правь [dataset.yaml](dataset.yaml). Бери **реальные вопросы граждан** (и ru, и kk).
Для каждого — что ответ обязан содержать и на что сослаться. Минимум один kk-кейс
на каждый ru — казахский это главный риск (low-resource эмбеддинг).

## Как этим тюнить (рабочий цикл)
Прогон даёт базовую цифру. Дальше меняй **по одному параметру** и сравнивай:

- **`CHUNK_TOP_K` / `TOP_K`** (`rag/.env`) — сколько контекста уходит в LLM. На маленькой
  точной базе меньше = чётче (меньше «воды» в ответе); на большой — наоборот. Старт: 12/40.
- **Reranker** (`RERANK_ENABLED=1` + эндпоинт `bge-reranker-v2-m3`) — обычно заметно
  поднимает попадание в нужную статью на юр-текстах.
- **Промпт** (`ragsvc/prompts.py`) — длина ответа, формат цитаты, поведение на отказе.
  Любую правку промпта проверяй этим набором ДО и ПОСЛЕ.

Меряй ru и kk отдельно — у них разный retrieval.
