# Spark-TTS-Kazakh — сервер казахского TTS (ПРЕЖНИЙ движок)

> ⚠️ **С 2026-08-17 основной казахский TTS — OmniVoice** (`omni_server/`,
> `TTS_KK_PROVIDER=omni`): офлайн, как Spark, но без вырожденной генерации и без
> квадратичного роста времени от длины. Этот сервис оставлен как второй
> офлайн-движок и на случай отката; всё ниже по-прежнему верно.

Отдельный сервис: качественный казахский синтез (Spark-TTS, LLM-based, с клонированием
голоса). Основной API зовёт его по HTTP. Вынесен отдельно, т.к. версии (torch 2.8,
transformers 4.46) несовместимы с основным API и другими TTS-серверами.

```
Основной API  ──HTTP──▶  Spark-сервер (этот)  ──▶  Spark-TTS-Kazakh
   POST /tts {"text","language"}                возвращает WAV
```

## Установка и запуск (из корня проекта)
```bash
bash spark_server/setup.sh    # venv + фреймворк + модель (нужен интернет)
bash spark_server/run.sh      # слушает порт 8809
```
Проверка:
```bash
curl -X POST http://localhost:8809/tts \
  -H 'Content-Type: application/json' \
  -d '{"text":"Сәлеметсіз бе!","language":"kazakh"}' --output test.wav
```

## Подключение к основному API
В `.env` основного проекта:
```
TTS_KK_PROVIDER=spark
SPARK_URL=http://localhost:8809/tts
```

## Голос
- Без референса — режим по полу/тону (`SPARK_GENDER=male|female`, `SPARK_PITCH`, `SPARK_SPEED`).
- **Клонирование:** дай образец 3–10 сек (`SPARK_SPEAKER_WAV=ref.wav`) — заговорит этим голосом.
  В этом режиме темп берётся из образца, а `SPARK_SPEED`/`SPARK_PITCH` молча игнорируются.
  Текущий режим видно в `/health` → `"cloning": true|false`.

## ⚠️ SPARK_SPEED — не крутить. Разгонять речь надо плеером (проверено 2026-07-16)

Соблазн ускорить речь ручкой модели выглядит логичным, но это **плохой размен**:

| Значение | Что даёт | Чем платим |
|---|---|---|
| `very_high` | — | **Ломает всегда**: вырожденная генерация (0 токенов), звука нет вовсе |
| `high` | ~10% темпа (8.00 c → 7.10 c) | Вырожденная генерация **случайно**: один и тот же текст то озвучивается, то падает с 422 |
| `moderate` | базовый темп | **Ничем** — 6/6 прогонов без отказов |

422 на **одном** куске рушит **весь** ответ, поэтому 10% темпа того не стоят.
Держим `moderate`, а скорость берём на стороне плеера (`SPEECH_RATE` в
`video_ui/static/index.html`): `playbackRate` ускоряет ровно во столько, сколько
задано, ничего не стоит (звук уже готов) и не может уронить синтез.
`moderate/1.4 = 5.71 c` против `high/1.25 = 5.68 c` — на слух то же самое, без риска.

## ⚠️ Spark нестабилен сам по себе — держим ретраи

Даже на `moderate` модель изредка выдаёт вырожденную генерацию (0 семантических
токенов). На это есть `SPARK_RETRIES` (по умолчанию в `run.sh` — 5, т.е. 6 попыток);
если все попытки пустые, сервер отдаёт **422**, а не тишину. Дефолтных 3 попыток мало.

Недетерминирован и в длине: один и тот же текст на 181 симв. дал 12.70 / 13.60 /
14.44 / 13.72 / 16.88 / 15.96 c. Это не поломка — просто так работает модель.

## Где запускать
- CPU работает, но LLM-генерация медленная и растёт **квадратично** от длины текста:
  100 симв. → ~18 c, 330 симв. → ~117 c. Поэтому длинный ответ режется на куски
  (см. `TTS_MAX_CHARS` / `TTS_KK_MAX_CHARS` в `app/config.py`), а не отдаётся целиком.
- На GPU (`SPARK_DEVICE=cuda`) — заметно быстрее. Для боя — GPU.
- Лимит текста у самого сервера — `SPARK_MAX_CHARS` (3000), он куда выше, чем 180
  у F5; не путать их (см. `TTS_KK_MAX_CHARS`).
