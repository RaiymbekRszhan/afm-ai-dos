## ⚠️ Код варианта 1 остаётся в бэкенде (не перенесён — вшит в маршруты)

Логически он «здесь», физически — в общем бэкенде, потому что вырезать его = править
общий эндпоинт `/voice` (его кэш ответа читает `aidos-audio.js`), а это ломает и
вариант 2. Манифест — что именно относится к варианту 1 и где лежит:

| Что | Файл | Роль |
|---|---|---|
| `/avatar` | `app/static/avatar.html` | киоск-страница: iframe с плеером + кнопка/микрофон, панель ответа |
| `/player` | `app/main.py` (`_PLAYER_HTML`) | наш плеер: `player.js` (с render-ПК) + `aidos-audio.js` (свой) |
| проигрывание звука зрителю | `app/static/aidos-audio.js` | ловит `aidos_speak`, качает WAV, играет со сдвигом `SYNC_OFFSET_MS` |
| `/last_answer*`, `/answer/<id>.wav` | `app/main.py` | WAV ответа (+`X-Id`), CORS открыт; heartbeat аватар-клиента |
| `RENDER_PC_HOST`, `LAST_ANSWER_TOKEN` | `app/config.py` / `.env` | IP render-ПК (в одном месте) и токен эндпоинтов ноды |

Чтобы **полностью** извлечь/убрать вариант 1 из бэкенда — это отдельная задача, которую
безопаснее делать с запущенным стеком, чтобы проверить, что `/voice` не сломался.

## Как это собрано (Path B)

Плеер Pixel Streaming отдаёт **сам бэкенд** (`/player`, тот же origin, что `/avatar`).
Движковый `player.js` грузится кросс-origin с render-ПК, а наш `aidos-audio.js` — с того
же origin, что и страница, и без CORS ловит событие речи и играет WAV.

**Поток звука к зрителю:**
1. Гражданин жмёт «Задать вопрос» → микрофон → `POST /voice` (STT→RAG→TTS). Бэкенд
   кэширует WAV последнего ответа с новым `id` (`X-Id`).
2. `aidos-audio.js` опрашивает `GET /last_answer/id` (раз в `POLL_MS`) и, увидев новый
   `id`, **заранее** качает `GET /answer/<id>.wav` (blob) — готов к мгновенному старту.
3. Unreal прямо перед началом речи шлёт по data-каналу
   `{"type":"aidos_speak","id":"<id>"}`.
4. `aidos-audio.js` по событию играет подготовленный WAV **со сдвигом `SYNC_OFFSET_MS`**
   (подгоняем под губы). Всё same-origin → без CORS.

## Render-ПК (Windows, Unreal)
- Встроенный сигналинг Pixel Streaming: HTTP-фронтенд и сигналинг игроков на **порту 80**,
  id стримера — **Editor**. `http://<RENDER_PC>/player.js` должен отдаваться.
- Unreal шлёт в data-канал `{"type":"aidos_speak","id":"<ID_ОТВЕТА>"}` ровно перед началом
  артикуляции. `<ID_ОТВЕТА>` = `X-Id` из `/last_answer`. Контракт — [AVATAR.md](AVATAR.md).
- `aidos-audio.js` сам привяжется к `window.pixelStreaming`. Если объект называется иначе —
  `window.aidosAttachPixelStreaming(<ваш объект>)`. Проверка в консоли плеера:
  `[aidos] attached to PixelStreaming (response listener 'aidos')`.

## Смена IP render-ПК — правим ОДНО место
IP живёт только в `RENDER_PC_HOST` (`.env`) → `settings.render_pc_host`. `/player` берёт
из него и `player.js`, и дефолтный `ss` (если iframe не передал — 307-редирект с
`ss=ws://<RENDER_PC_HOST>:80`). В `avatar.html` IP нет. Сменилась нода — правим `.env`,
рестарт бэкенда.

## Автозвук (autoplay) — плашки нет
Браузер не даёт играть звук без жеста. `avatar.html` (тот же origin, что `/player`)
разблокирует звук в плеере через `iframe.contentWindow.aidosUnlock()`: в начале обработчика
кнопки «Задать вопрос» и на первый `pointerdown`/`keydown` (запасной путь). `unlockAudio()`
идемпотентна, «благословляет» и `AudioContext`, и `HTMLAudio`.

## Настройки `aidos-audio.js` (вверху файла)
```js
const BACKEND = "";            // пусто = same-origin (Path B). НЕ трогать при переезде.
const SYNC_OFFSET_MS = 800;    // + = задержать звук (мс). ГЛАВНЫЙ тюнинг под губы, 100–800.
const POLL_MS = 1000;          // период предзагрузки нового ответа
const SHOW_UNLOCK_OVERLAY = false;  // видимая плашка выключена (разблокирует родитель)
```
`SYNC_OFFSET_MS` — единственное, что крутят вживую: звук опережает губы → увеличить,
отстаёт → уменьшить. Правится в одном файле, hard-refresh.

## Открыть киоск
```
http://<LINUX-IP>:8000/avatar?kiosk=1&ar=9/16
```
`?ar=` — пропорция области видео под аспект рендера UE. Микрофон по http требует
secure-context (то же, что и для варианта 2 — см. `PILOT.md`).
