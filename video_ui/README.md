# Киоск-страница «видео-аватар» (:8100)

Фронтенд пилота: заранее записанные ролики аватара (idle + «говорит») поверх
живого голосового пайплайна бэкенда (:8000). Пока тихо — крутится idle; на ответ
включается немой ролик «говорит», зациклённый на длину звука. Поверх пайплайна:
таблицы и графики из базы, QR-коды порталов, печать образцов заявлений на принтер
киоска, караоке-подсветка, увеличение по тапу, автопрокрутка.

## Как это работает

```
микрофон (браузер :8100) → POST :8100/voice ──прокси──► :8000/voice
                                                          │ STT → RAG → TTS
                          ◄──── WAV + X-Question/X-Answer ┘
   <audio> играет WAV  +  <video id=talk> (немой, зациклен) поверх idle
   звук кончился → возвращаемся на idle.mp4
```

Прокси нужен, чтобы страница и её запросы были **same-origin** — иначе в бэкенд
пришлось бы добавлять CORS.

## Тесты (чистые функции рендера)

`static/answer_render.js` (парсинг таблиц, QR-ссылки, вес слов для караоке,
детект печати образцов) не тянет ни браузер, ни зависимости — офлайн `node --test`:

```bash
node --test video_ui/static/answer_render.test.js
```

## Ролики (положить перед запуском)

```
video_ui/static/video/idle.mp4   — аватар стоит/молчит (крутится в цикле всегда)
video_ui/static/video/talk.mp4   — аватар говорит, ЛЮБОЙ текст (звук не важен — мы его глушим)
```

Требования — минимальные, ролики не обязаны совпадать по длине с ответом:
- **`talk.mp4` зацикливается** на всю длину звука, поэтому короткого ролика (5–10 c)
  достаточно даже для минутного ответа. Лучше, если начало и конец ролика похожи —
  тогда шов на стыке цикла не бросается в глаза.
- **`idle.mp4`** — тоже в цикле; чем длиннее и спокойнее, тем естественнее.
- Формат: **MP4/H.264 + AAC** (самый совместимый с браузерами). Звук в файлах может
  быть — он всё равно заглушён (`muted`).
- Оба ролика лучше одного разрешения/кадрирования — тогда переключение незаметно.
- Аспект подгоняется параметром `?ar=` (см. ниже), кадр масштабируется `object-fit: cover`.
- ⚠️ В текущие ролики (1080×1152) **вшиты чёрные поля по 150px сверху/снизу** —
  полезный контент 1080×852. Киоск это компенсирует: дефолтный аспект области =
  `1080/852` + `cover` срезает ровно вшитые поля (без черноты и без обрезки лица).
  Замените ролики на чистые — поправьте дефолт `--stage-ar` в `index.html` (аспект
  кадра) или передавайте `?ar=`.

⚠️ **Имена — строго в нижнем регистре.** macOS не различает регистр, поэтому `Idle.mp4`
там играет как ни в чём не бывало, а на **Linux (сервер АФМ) регистр важен** — те же файлы
дадут 404 и чёрный экран ровно на пилоте. `/health` сверяет имена точно (через `listdir`),
поэтому ловит это и на маке.

Проверить, что файлы на месте: `curl http://localhost:8100/health` → `"videos": {"idle.mp4": true, "talk.mp4": true}`.

## Запуск

```bash
bash run_api.sh          # весь стек одной командой, ВКЛЮЧАЯ эту страницу (:8100)
```

Отдельный запуск страницы (`bash video_ui/run.sh`) нужен только когда бэкенд уже
работает где-то ещё; выключить её в общем стеке — `WITH_VIDEO_UI=0 bash run_api.sh`.

Открыть: `http://localhost:8100/` (киоск: `http://<IP>:8100/?kiosk=1&ar=9/16`).

Переменные окружения:

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `AIDOS_BACKEND` | `http://localhost:8000` | Рабочий бэкенд, если он на другой машине |
| `AIDOS_BACKEND_TIMEOUT` | `450` | Таймаут `/voice` (TTS на CPU может идти минуты); должен быть заметно больше `rag_timeout` бэкенда (260 с, `app/config.py`) |
| `AIDOS_MAX_UPLOAD_MB` | `25` | Лимит размера загружаемого аудио, зеркалит `max_upload_mb` бэкенда |
| `VIDEO_UI_PORT` | `8100` | Порт демо |

Параметры страницы: `?kiosk=1` — режим киоска (крупные кнопки, бейдж языка,
чёрный фон, авто-полный-экран по первому тапу); `?ar=9/16` (или `1/1`, `16/9`) —
пропорция области видео под аспект роликов; `?demo=1` — образец ответа с таблицей
и графиком без бэкенда (проверка рендера).

**Полный экран.** В киоске (`?kiosk=1`) на первом же тапе по экрану страница
уходит в полный экран (Fullscreen API), пряча адресную строку — чтобы киоск не
выглядел как вкладка браузера. Fullscreen API работает только из жеста
пользователя, поэтому это происходит на касании, а не при загрузке. Надёжнее в
проде — запускать браузер сразу в киоск-режиме, тогда хром не появится вообще:
`chrome --kiosk --app=http://<IP>:8100/?kiosk=1` (снимает и «Активация Windows», и
панель задач). Фон страницы и «карточки» — чёрные: на киоске текст читается
контрастнее, а белые QR-карточки на чёрном подсвечиваются ярче.

## Таблицы и графики из базы

Если в базе есть перечислимые числовые данные по вопросу (штрафы по категориям,
пороги, сроки), RAG прикладывает к устному ответу блок для экрана (правило 7
промпта, `rag/ragsvc/prompts.py`):

```
[ТАБЛИЦА]
Категория нарушителя | Штраф
Физические лица | 100 МРП
[/ТАБЛИЦА]
```

- **Голос его не читает**: оркестратор вырезает блок перед синтезом
  (`app/clients/tts.py` → `strip_display_blocks`), в `X-Answer` текст уходит целиком.
- **Экран рендерит** (`static/answer_render.js`, ноль зависимостей — сеть АФМ без
  интернета): таблица + горизонтальный бар-чарт, если колонка числовая («100 МРП» →
  100) и строк не больше десяти. Длина бара — по числу, подпись у бара — текст ячейки
  как в базе. DOM строится только через `textContent` (текст из LLM, innerHTML был бы
  XSS на публичном экране).
- Блок без маркеров (LLM забыл) тоже ловится: 2+ подряд строки с `|` считаются таблицей.

Проверить без бэкенда: `http://localhost:8100/?demo=1` (и `?demo=1&kiosk=1`).

## QR-коды порталов

Упомянул ответ портал или ссылку — появляется QR-карточка (гражданин сканирует
телефоном). В киоске она **висит поверх видео, на груди/галстуке аватара**
(`#qrOverlay` в `index.html`), умеренного размера и по центру — гражданин снимает
код, не теряя аватара из виду (не отдельным блоком под текстом). Показ —
`renderAnswer(out, text, qrOverlay)` кладёт коды в overlay и включает его классом
`.on`; несколько порталов встают в ряд. Именованные порталы берутся из словаря
ПРОВЕРЕННЫХ адресов `QR_PORTALS` в `static/answer_render.js` (e-Otinish →
eotinish.kz, qamqor.gov.kz, eGov, «сайт Агентства» → страница АФМ на gov.kz);
явные домены из текста ловятся регекспом. Новый портал = одна строка в словаре.
Позиция/размер QR — `bottom`/`clamp(...vw)` у `#qrOverlay` (заменишь ролики —
поправь `bottom` под новый кадр аватара). Генерация QR — офлайн, `static/qrcode.js`
(vendored [qrcode-generator](https://github.com/kazuhikoarase/qrcode-generator), MIT).

## Печать образцов заявлений

Если ответ про подачу заявления/жалобы или запись на личный приём, рядом с
«Задать вопрос» появляется зелёная кнопка **«🖨 Распечатать образец»**, а аватар
**голосом предлагает** распечатать (фраза-приглашение — часть ответа). Клик
открывает меню выбора документа (язык переключается тут же), выбор — печать бланка.

- **Когда предлагать и приглашение — решает БЭКЕНД.** В `/voice`
  (`app/service.py`): `detect_print_templates(answer)` по словам ответа
  («заявление/обращение/жалоба/подать/арыз/шағым/өтініш» → ФЛ и ЮЛ; «личный
  приём/жеке қабылдау» → приём; на справочных ответах — пусто), а
  `with_print_offer()` **дописывает приглашение В ОТВЕТ до синтеза** — поэтому
  аватар его проговаривает и оно же уходит в X-Answer (читается органично, как
  часть ответа, отдельной плашки НЕТ). Вставляется ПЕРЕД блоком `[ТАБЛИЦА]` —
  иначе `strip_display_blocks` срезал бы его вместе с незакрытой таблицей. Список
  образцов уходит заголовком **`X-Print: fl,ul`** (проксируется через :8100).
  Фронт (`updatePrintButton`) берёт образцы из X-Print; в `?demo=1` (без бэкенда)
  — фолбэк на `detectPrintTemplates` в `static/answer_render.js`.
- **Что печатается** — `static/templates/form.html?type=fl|ul|priem&lang=ru|kz`:
  один параметризованный документ на все шесть форм, чистый печатный HTML (A4).
  Тексты воспроизведены из официальных `.docx` (`Downloads/Образцы/`): ФЛ, ЮЛ,
  запись на приём — рус/каз. Меняются официальные формы — правится `form.html`
  (шесть функций в объекте `FORMS`). LibreOffice в сети АФМ нет, поэтому не PDF, а
  HTML — браузер печатает его нативно.
- **Как печатается** — бланк грузится в скрытый `<iframe id="printFrame">`, по
  загрузке вызывается его `print()`. Язык бланка — по языку вопроса (в меню можно
  сменить).
- **Тихая печать + полный экран на киоске (ВАЖНО).** Chrome на киоске запускают
  с **`--kiosk --kiosk-printing`**:
  - `--kiosk-printing` — лист уходит на принтер по умолчанию БЕЗ диалога (иначе
    открывается диалог и печать надо подтверждать второй раз);
  - `--kiosk` — полноэкранный режим уровня браузера. Именно поэтому под ним НЕ
    используем JS Fullscreen API (`enterFullscreen` пропускает, если окно и так
    во весь экран): `print()` СБРАСЫВАЕТ Fullscreen API, и без этой защиты киоск
    «выпадал» из полного экрана после печати.

  Пример: `chrome --kiosk --kiosk-printing "http://<IP>:8100/?kiosk=1"` (задать
  принтер по умолчанию в системе).

## Темп речи (`SPEECH_RATE` в `static/index.html`)

```js
const SPEECH_RATE = { kazakh: 1.4, russian: 1.0 };
```

Ускоряем **здесь**, а не в самом TTS: `playbackRate` ускоряет ровно во столько, сколько
задано, ничего не стоит (звук уже готов), `preservesPitch` держит тембр — и, в отличие
от ручки модели, не может уронить синтез.

- **kazakh 1.4** — Spark говорит медленно, но разгонять его `SPARK_SPEED` нельзя: на
  `high` он случайно выдаёт вырожденную генерацию и роняет ответ (см.
  [spark_server/README.md](../spark_server/README.md)). Поэтому Spark держим на
  безопасном `moderate`, а скорость берём тут.
- **russian 1.0** — F5 говорит в нормальном темпе. Если покажется медленным, правильнее
  сменить референс (`refs/ref_ru_f5_padded.wav`): F5 клонирует голос вместе с темпом, и это
  звучит естественнее растягивания плеером.

Темп берётся по языку, на котором **спрашивали** (не по текущему в селекте: синтез идёт
секунды, за это время язык можно переключить). 1.2–1.4 звучит естественно, выше — тараторит.

## Нюансы

- **Микрофон по http требует secure-context**:
  по `http://<IP>:8100` браузер не даст записать звук. Лечится флагом
  `chrome://flags/#unsafely-treat-insecure-origin-as-secure` (вписать `http://<IP>:8100`)
  или HTTPS. Подробно — `PILOT.md` §B8.
- **Микрофон в режиме `--kiosk`**: в киоск-режиме Chrome НЕ показывает окно
  разрешения микрофона — выдать доступ/выбрать устройство некуда, запись не
  стартует. Лечится флагом запуска **`--use-fake-ui-for-media-stream`** (доступ
  выдаётся автоматически, берётся микрофон ПО УМОЛЧАНИЮ из Windows → задать нужный
  в «Параметры → Звук → Ввод»). Оба флага уже в `video_ui/Запуск-киоска.bat`.
- **Звук ответа требует жеста** — снимается автоматически: по клику «Задать вопрос»
  проигрывается тишина-заглушка, поэтому пришедший через секунды WAV уже играет.
  Отдельной плашки «включить звук» нет. Немое видео (`muted`) жеста не требует —
  idle крутится сразу.
- **Новых зависимостей нет** — используется основной `.venv`
  (`fastapi`/`uvicorn`/`httpx`/`python-multipart` уже там).
- **Ролики в git**: если они тяжёлые (десятки МБ), не коммить — копировать на сервер
  руками (`scp`), иначе репозиторий распухнет.
